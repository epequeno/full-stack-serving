# 0014 — Commit the gate's output

- **Status:** proposed
- **Date:** 2026-10-11

## Context

ADR 0008's gate is this repo's central claim: a fresh run reproduces every committed finding. The
gate is `make verify LEVEL=<l>`, and every PASS this repo reports is a sentence somebody wrote
into a README after running it:

- `results/l1-k8s/README.md` — "**2026-10-10: PASS.**"
- `results/l4-otel/README.md` — "**2026-10-11: PASS.**"
- `AGENTS.md` — "both currently pass — verified 2026-10-11".

None of it is checkable from a checkout. That is the failure mode ADR 0008 exists to prevent,
one level up: the gate is *asserted* rather than *shown*, so a reader has to trust the author
that it ran at all.

ADR 0008 also requires that `make verify` never write into `results/`. That rule was written for
**measurements** — a run that overwrites committed evidence destroys the thing it is checking —
and it is silent about the record of the run itself.

## Decision

**The gate's output is committed, under the level it gates: `results/<level>/gates/`.**

- `make gate-log LEVEL=<l>` runs the same verify and tees its full output to
  `results/<level>/gates/verify-<UTC timestamp>.txt` (`tools/gate-log.sh`). It exits with the
  gate's own status, so it works from a terminal and from a script.
- **It is an audit record, not measurement.** Nothing reads it, no number is taken from it, and it
  is the one thing under `results/` that `make measure` does not regenerate. ADR 0008's rule is
  unchanged for every file that holds a number: `make verify` still writes only to scratch.
- **A failing gate is logged too.** The log ends with `result: PASS` or `result: FAIL (exit N)`.
  A FAIL is evidence, not an omission — ADR 0008's remedy for a changed verdict (more runs per
  cell, or a restated finding) is not weakened by having the failure on file.
- **The header is the provenance.** Commit SHA, host `uname`, UTC start time, and the number of
  uncommitted paths at run time. A log whose `git:` line is not the commit under review says so on
  its face.
- The level's `env.md` is **not** copied into the log. `make verify` already writes the
  environment it measured in; the log points at the run rather than duplicating it.

## Consequences

- The central claim becomes checkable from a clone: `ls results/*/gates/` shows when each level was
  last gated and against which commit.
- `results/` gains files that `make measure` does not regenerate. That is a real exception to
  `AGENTS.md`'s "anything that cannot be regenerated by `make measure` should not be in
  `results/`", named here and in `measure/README.md`. It is safe because a gate log asserts
  nothing on its own — the finding it reproduces is still in `findings.json`, and the log is only
  the evidence that the reproduction was run.
- **Logs accumulate.** Nothing prunes them. If they become noise, keeping only the latest per
  level is a change to this decision, which takes a new record — not a silent habit.
- **L0 gets no log.** It is the baseline and commits no findings (ADR 0008), so there is nothing
  to gate; `tools/gate-log.sh` refuses the level rather than writing an empty file.
- **Status.** This record is `proposed` and the mechanism ships with it, so the runbook can use
  it. The owner accepts it when the first real log is committed (runbook step 1) — that log is
  what tests the shape.
