# Prompt fixtures

Committed so every level replays the same workload. Two sets, same size and shape, so the only
difference between them is whether prefixes are shared:

| File | What | Used for |
|---|---|---|
| `distinct.jsonl` | 256 prompts, no shared prefix | L0, L1, L3: the baseline workload, where prefix caching cannot help |
| `shared-prefix.jsonl` | 256 prompts in 8 groups of 32; each group shares an ~800-word body | L2: prefix-aware vs round-robin routing |

Each prompt is ~843 words: an 800-word body plus a 40-word per-request suffix and a short
question line. `max_tokens` is 128 with `ignore_eos`, so output length is the same on every run.

## Provenance

Generated by `generate.py` from a word list written for this repo and a fixed seed. **No
third-party text or dataset is used, so there is nothing to attribute or relicense.**
`generate.py --check` regenerates in memory and compares with the committed files, and
`SHA256SUMS` pins them. The output does not depend on the Python version or `PYTHONHASHSEED`
(checked under two hash seeds).

## Decisions worth knowing

- **Request order is hashed, not `i % groups`.** A periodic order aliases with round-robin: with 8
  groups over 2 replicas, every group would land on one replica and the baseline would look
  cache-perfect. The generator fails if any group lands on fewer than 2 replicas under round-robin
  over 2, 3 or 4 replicas.
- **A ceiling for L2.** With 8 groups the first request of each group cannot hit, so at most 224 of
  256 requests (87.5%) can reuse a prefix, and only if the cache holds all 8 bodies. A measured hit
  rate is read against that ceiling, not against 100%.
- **Uniform length is a simplification.** Every prompt has the same word count, which keeps the
  comparison clean and does not resemble real traffic. Findings from these fixtures say nothing
  about variable-length workloads.
- **Random word salad, not natural text.** It tokenises worse than prose, and a model's behaviour
  on it is irrelevant here because output length is forced. Token counts are not claimed; L0
  measures them from the server's `usage`.

## Not verified, to check at L0

- **Token length against the chosen model's context window.** Words are not tokens, and rare words
  split into several. Prompt tokens plus 128 output must fit, with the batch limits the engine is
  configured with.
- **`ignore_eos` is a vLLM request extension.** Another engine may name it differently or not
  support it, in which case output length is no longer fixed and TPOT comparisons need care.
- **Whether `distinct` really defeats prefix caching.** The bodies share no words in order, but
  the check that the server's prefix-cache hit counter stays near zero on this set is an L0 result,
  not an assumption.
